# When & How to use Git Cherry-Pick
> **Track:** Developer Tools & Git | **Day:** Thursday | **Date:** 2026-10-18

**Pick specific commits across branches like a Senior Engineer**

## 📌 Overview
git cherry-pick allows you to apply a specific commit from one branch onto your current branch without merging the entire history.

## 💡 Key Highlights
- Use Case 1 (Hotfix): You fixed a bug in a development branch and need to port ONLY that fix to the production branch immediately.
- Use Case 2 (Accidental Branching): You made a commit on main instead of a feature branch.
- Syntax: git checkout <target-branch> -> git cherry-pick <commit-hash>
- Pro Tip: If conflicts occur, resolve them and run 'git cherry-pick --continue', or abort using 'git cherry-pick --abort'.

## 💻 Code Example
```
# 1. Find the commit hash from git log
git log --oneline
# a1b2c3d Fix payment gateway crash

# 2. Switch to production branch
git checkout main

# 3. Cherry-pick only that commit
git cherry-pick a1b2c3d
```

## ⚡ Complexity & Performance
- **Safety:** `Non-destructive: generates a new SHA hash with the same diff`
- **Best Practice:** `Use sparingly to avoid duplicate commits in long-lived branches`

## 🎯 Interview Tip
> [!TIP]
> Interviewers love asking how cherry-pick differs from rebase and merge: merge joins branches, rebase rewrites linear history, cherry-pick copies individual commits.
