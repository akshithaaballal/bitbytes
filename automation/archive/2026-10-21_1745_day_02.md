# Caching Strategies: Cache-Aside vs Write-Through
> **Track:** System Design 101 | **Day:** Tuesday | **Date:** 2026-10-21

**How large-scale distributed systems achieve sub-millisecond reads**

## 📌 Overview
Caching places high-frequency data in lightning-fast in-memory stores (like Redis or Memcached) to prevent exhausting your primary database.

## 💡 Key Highlights
- Cache-Aside (Lazy Loading): The application first checks cache. If cache miss, reads from DB and writes to cache. Great for read-heavy workloads.
- Write-Through: App writes data to the cache, which immediately writes to the DB. High consistency, slightly slower write latency.
- Eviction Policies: LRU (Least Recently Used) is most common. LFU (Least Frequently Used) is best for long-term popularity curves.

## 💻 Code Example
```python
# Cache-Aside Pattern in Python/Redis
def get_user_profile(user_id):
    cached = redis_client.get(f"user:{user_id}")
    if cached:
        return json.loads(cached)
    
    # Cache miss: fetch from primary database
    user = db.query_user(user_id)
    redis_client.setex(f"user:{user_id}", 3600, json.dumps(user))
    return user
```

## ⚡ Complexity & Performance
- **Cache Hit:** `< 5ms (RAM access)`
- **Db Read:** `50ms - 500ms (Disk I/O / Network)`
