# Process vs Thread Explained Visually
> **Track:** Core CS: Operating Systems | **Day:** Wednesday | **Date:** 2026-10-24

**The #1 favorite question asked in university exams & technical rounds**

## 📌 Overview
A Process is an executing program with its own dedicated memory space, whereas a Thread is a lightweight unit of execution within that process.

## 💡 Key Highlights
- Memory Isolation: Processes have independent virtual address spaces (Stack, Heap, Code). If one process crashes, others are unaffected.
- Shared Memory: Threads within the same process share the Heap and Data segments, but have their own private Registers and Stack.
- Context Switching: Thread switching is significantly faster than process switching because MMU page tables do not need to be flushed.
- IPC: Processes communicate via Inter-Process Communication (Pipes, Sockets, Shared Memory). Threads communicate directly through shared memory variables.

## 💻 Code Example
```python
# Python Multiprocessing vs Threading
from threading import Thread
from multiprocessing import Process

# Multi-threading: great for I/O bound tasks (Network, Disk)
t1 = Thread(target=fetch_api_data)
t1.start()

# Multi-processing: bypasses Python GIL for CPU-bound tasks
p1 = Process(target=heavy_math_computation)
p1.start()
```

## ⚡ Complexity & Performance
- **Creation Cost:** `Process (High overhead) vs Thread (Lightweight)`
- **Communication:** `Process (IPC required) vs Thread (Shared heap)`

## 🎯 Interview Tip
> [!TIP]
> If asked about Python specifically, remember the GIL (Global Interpreter Lock): threads don't run in true parallel on multi-core for CPU tasks; use multiprocessing instead!
